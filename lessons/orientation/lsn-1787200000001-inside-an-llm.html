Inside an LLM: The Parts and What Each Does

Follow one sentence all the way through — from text, to numbers, to the next word.

You can use these models productively without knowing what's inside them. But almost every practical question — why context costs what it does, why a fine-tune changes behaviour, what quantization actually shrinks, why the tokenizer matters — has an answer that lives in the architecture. This lesson walks one sentence through the whole machine.

1 · The tokenizer

Before any maths, text is split into tokens and each is looked up as an integer. The tokenizer is a fixed vocabulary — typically 32,000 to 200,000 entries — built once before training and never changed afterwards.

It explains several things that otherwise look arbitrary: why models are bad at counting letters in a word (they never see letters), why unusual names cost more tokens than common ones, and why non-English text is often more expensive — the vocabulary was fitted mostly to English, so other languages fragment into more pieces.

2 · Embeddings and position

Each token id is looked up in an embedding matrix and becomes a vector of a few thousand numbers. This is the same idea as the embeddings used for retrieval, learned here as part of the model.

Because attention compares all positions equally and has no inherent sense of order, position must be added explicitly — in most current models through rotary position embeddings. This is also why extending a model's context beyond what it was trained on is largely a positional-encoding problem rather than a memory one.

3 · The transformer blocks

The bulk of the model: the same block repeated dozens of times, each containing two operations that alternate.

Attention
Tokens exchange information
Each token gathers from every other, weighted by relevance. The mechanism the algorithms lesson covers in detail.
Feed-forward network
Each token processes alone
A small network applied to every position independently. Typically two-thirds of all parameters — most of the model's stored knowledge lives here, not in attention.
Residual connections
Add the input back to the output
Lets signal and gradients pass through 80 layers without degrading. Without these, deep networks don't train.
Layer normalisation
Rescale the numbers
Keeps values in a workable range so training stays stable.
Where the knowledge actually sitsIt's tempting to think of attention as the clever part and the feed-forward layers as plumbing. It's closer to the reverse. Attention decides which information to route where; the feed-forward layers hold most of the learned facts, and they're where most of the parameters are. When you hear a model 'knows' something, it is largely these layers.

4 · The output head

After the final block, the vector at the last position is multiplied by an unembedding matrix to produce one score — a logit — for every token in the vocabulary. Softmax turns those scores into probabilities summing to one.

Note what is thrown away: the model computed a rich representation at every position, and generation uses only the last. The others aren't wasted — they're cached, which is exactly what the KV cache holds.

5 · Sampling

A probability distribution over the vocabulary isn't yet a word. Temperature, top-k and top-p reshape that distribution and one token is drawn. Then the whole process runs again with that token appended — one full pass through the entire model per token generated.

The parts as files on disk

Download an open model and you get the same components, made concrete:

config.json
The architecture
Layer count, hidden size, attention heads, vocabulary size, context length. The blueprint.
tokenizer.json
The vocabulary
Must match the weights exactly. Mismatch it and you get fluent nonsense — a classic and baffling bug.
*.safetensors
The weights
The actual learned numbers, at full precision. What fine-tuning modifies.
*.gguf
Weights, quantized and packaged
Config, tokenizer and quantized weights in one self-contained file for local serving.
chat template
Turn structure
How system, user and assistant turns are formatted into one string. Get this wrong and quality drops for no visible reason.
What each technique actually touchesPrompting changes the input only. Fine-tuning adjusts the weights — usually the feed-forward layers most. LoRA freezes the original weights and trains small add-on matrices alongside them. Quantization stores the same weights in fewer bits. RAG changes nothing about the model at all; it changes what's in the context. Knowing which layer of the machine each one touches tells you which problem each can and cannot solve.

The size numbers, made concrete

A 7-billion-parameter model has roughly 32 blocks, a hidden size around 4096, 32 attention heads, and a vocabulary near 32,000. At 16-bit precision the weights alone are about 14GB — most of it in the feed-forward layers. Every one of those parameters is touched for every token generated, which is why local inference is memory-bandwidth bound and why quantization speeds things up as well as shrinking them.
