Convolutions, and What a CNN Assumes

A grid is not a list, and building that in rather than learning it is the whole idea.

A convolutional neural network (CNN) is the architecture that made computer vision work, and it is still the right answer for a large class of problems that this course's vision-language material does not serve. Its central idea is also the cleanest example in the whole program of an inductive bias — an assumption about the data built into the architecture rather than learned from examples — which is what makes it worth a lesson even if you never train one.

The problem with treating an image as a list of numbers

A fully-connected layer takes every input and connects it to every output. Feed it a modest 224 by 224 colour image and the input is about 150,000 numbers; connect that to a thousand units and that one layer holds roughly 150 million parameters. The next layer starts again from scratch.

The parameter count is the smaller problem. The larger one is that the layer has been told nothing about the picture. Pixel (10, 10) and pixel (10, 11) are neighbours and it does not know; a cat in the top-left and the same cat in the bottom-right are unrelated inputs and it has to learn each position separately. Every fact about the grid has to be discovered from data that could just as well have been shuffled.

What a convolution does instead

Convolution (kernel)
A small window of weights
Typically three by three or five by five. It is placed over a patch of the image, multiplied elementwise, and summed to one number. That number says how strongly this patch matches what the kernel is looking for.
Sliding it
The same weights, everywhere
The kernel moves across the whole image and the weights do not change as it moves. This is weight sharing, and it encodes the assumption that a feature worth detecting is worth detecting anywhere.
Locality
Only neighbours are combined
A unit sees a small patch rather than the whole image, which encodes the assumption that nearby pixels are related and distant ones mostly are not.
Stacking and pooling
Where the reach comes from
One layer sees three pixels; a layer above it sees three of those, and so on. The receptive field grows with depth, which is how a network of small windows ends up responding to whole objects.
Worth knowing

An inductive bias buys data efficiency and costs generality. That is the trade, and it is not free in either direction.

Building locality and weight sharing into the architecture means the network does not have to learn them, so it reaches good performance on far less data than an unconstrained network would need. It also means the network cannot easily learn a relationship those assumptions forbid — something depending on absolute position, or on two distant regions jointly, is awkward for a CNN in a way it is not for an architecture with no such assumption.

For exampleThis is exactly why a vision transformer, which has almost no built-in assumption about the grid, needs substantially more data than a comparable CNN to reach the same accuracy — and why, given enough data, it overtakes. The CNN was handed a head start in the form of assumptions; past a certain data volume, learning the structure beats being told it.

Where this sits next to attention

The transformer lesson describes attention as letting every position look directly at every other. Read alongside this one, the two are opposite answers to the same question. A convolution says: nearby things are related, and a pattern means the same thing wherever it appears — here are those rules, do not learn them. Attention says: any position may matter to any other, work out which from the data.

Neither is strictly better and the difference is a data budget. Architectures with strong assumptions win when data is scarce; architectures with weak assumptions win when it is plentiful, because an assumption is only a gift while it happens to be true. Modern vision models mostly sit between the two, and hybrid designs that keep some locality while adding attention are common for exactly this reason.

When a CNN is still the right tool

For most applied work involving an image today, the honest first move is the one the previous lesson describes: send it to a vision-language model and ask. That is a few lines, needs no labelled data and no training, and handles the enormous range of questions nobody anticipated.

  • A narrow task, done constantly. Classifying one kind of defect on a production line, at high volume, where a per-image API cost and a network round trip are both unacceptable.
  • You have the labels. Tens of thousands of examples of your specific task, which is the situation where a small purpose-built model beats a general one.
  • The output is not language. A bounding box, a segmentation mask, a count — things a specialised head produces natively and a text model approximates.
  • It has to run on the device. A few megabytes on a camera or a phone, with no connection.
The deterministic-first argument applies here too

Before either option, ask whether the task needs learning at all. A great deal of practical image work — is this page blank, has the seal moved, is this barcode readable, are these two frames different — is answered by arithmetic on pixels with no model of any kind, faster and with a failure mode you can read. Classical computer vision did not stop working when deep learning arrived, and the ladder from Block 0 is the same ladder: rule, then classical method, then a small trained model, then a large general one.
