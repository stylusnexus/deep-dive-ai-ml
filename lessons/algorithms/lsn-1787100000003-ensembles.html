Ensembles: Bagging, Forests and Boosting

Why many mediocre models beat one good one — and which kind to reach for.

A single decision tree is unstable and overfits. Combine many of them correctly and you get one of the strongest algorithm families available for tabular data — still, in 2026, routinely beating neural networks on the kind of data most businesses actually have.

Two strategies, opposite in spirit

Bagging and random forests

Bagging (bootstrap aggregating) trains each tree on a random sample of the rows, drawn with replacement, then averages their predictions. Because the trees see different data, their errors are partly independent, and averaging cancels them.

A random forest adds a second source of randomness: at each split, only a random subset of features is considered. This stops every tree from picking the same dominant feature at the root, decorrelating them further. More decorrelation, more variance cancelled.

Why forests are the safe defaultA random forest is remarkably hard to overfit by adding trees — more trees converge toward a stable answer rather than degrading. It needs almost no tuning, handles mixed data types, and gives usable feature importances. When you need a strong tabular baseline in ten minutes, this is it.

Boosting

Boosting works sequentially. Train a weak, shallow tree. Look at what it got wrong. Train the next tree specifically to fix those errors. Repeat, adding each new tree's contribution scaled by a learning rate.

Gradient boosting formalises this: each new tree is fitted to the gradient of the loss — the residual errors — which is the same gradient descent idea from lesson 1, applied by adding models instead of adjusting weights. XGBoost, LightGBM and CatBoost are optimised implementations, and they win a great many tabular competitions.

Boosting will overfit if you let itUnlike forests, adding boosting rounds past the optimum makes the model worse. You need early stopping against a validation set, plus a low learning rate and shallow trees. More rounds is not more better.

Choosing between them

Random forest
Fast to a good answer
Little tuning, resistant to overfitting, strong default. Start here.
Gradient boosting
Higher ceiling, more care
Usually wins on tuned performance. Needs early stopping and learning-rate tuning.
Single tree
When you must explain it
Occasionally the right answer purely because a human has to read the logic.

For the turbine project in Block 2, run a random forest before the neural network. If the forest wins — which happens more often than the marketing around deep learning suggests — that is a real result, not a failure.
