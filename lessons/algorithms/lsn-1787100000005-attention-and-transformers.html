Attention and the Transformer

The algorithm every model in this program is built from.

Every LLM you use is a transformer, and the transformer's central mechanism is attention. You don't need the matrix algebra to work effectively with these models, but you do need the shape of the idea — because it explains context limits, cost curves, and why the KV cache exists.

The problem attention solves

To predict the next word in "The turbine that the engineers inspected last week finally ___", the model must connect "turbine" to "finally" across ten intervening words. Earlier architectures processed text in order and carried a running summary, which meant long-range connections faded. Attention lets every position look directly at every other position, at any distance, in one step.

Query, key, value

Each token produces three vectors. The query is what this token is looking for. The key is what each token offers. The value is the content it contributes. Compare one token's query against every key, turn the resulting scores into weights, and take a weighted sum of the values.

That's it: each token's new representation is a blend of all tokens, weighted by relevance. Stack this operation dozens of times, with several independent attention "heads" per layer learning different relationships, and you have a transformer.

Two details in that description have names worth having. The scores are turned into weights by a softmax, which forces them to be positive and to sum to one — so attention is always distributing a fixed budget of attention rather than adding more of it. And before the softmax the scores are divided by the square root of the key dimension, which is why the operation is properly called scaled dot-product attention. Without that division the scores grow with dimension, the softmax saturates, and gradients vanish; it is a small correction that the whole thing depends on.

What follows from the algorithm

  • Quadratic cost, in attention specifically. n tokens means n² comparisons, so doubling the context quadruples the attention work. Be careful carrying that to the whole model: attention is one part of a forward pass, the projections and feed-forward layers are linear in context, and the squared term does not overtake them until the context approaches the model’s hidden dimension. Block 3 measures this and finds prefill close to linear at retrieval-sized contexts.
  • Position must be added. Attention is order-blind by construction, so position information is injected separately (rotary embeddings, in most current models). Extending context beyond training length is largely a positional-encoding problem.
  • The KV cache is a direct consequence. Keys and values for previous tokens don't change as generation proceeds, so they're cached rather than recomputed. Lesson 2 of the vocabulary set, arriving from the other direction.
  • Parallel training. Unlike sequential architectures, all positions are processed at once during training. This is why transformers scaled and their predecessors didn't.
Why 'attention' is a fair nameThe weights are interpretable in a limited way — you can see which earlier tokens most influenced a prediction. Treat that as a debugging aid rather than an explanation; attention weights show where information flowed, not why the model concluded what it did.

What multiple heads are for

One attention operation produces one weighted blend. A layer runs several in parallel — typically eight to a hundred and twenty-eight — each with its own learned projections, and concatenates the results.

The reason is that a token relates to its context in more than one way at once. "Turbine" needs to connect to the verb that governs it, the adjective describing it, and the earlier mention it refers back to. One set of attention weights has to compromise across all three; several sets can specialise. Interpretability work has found heads that appear to track syntactic dependencies and heads that track coreference, though attributing clean single functions to heads is less reliable than early results suggested.

The variants you will meet by name

Multi-head attention (MHA)
The original
Every head has its own keys and values. Most expressive, largest KV cache.
Multi-query attention (MQA)
One set of keys and values for all heads
The far end of the same idea: every query head shares a single key-value head. Smallest possible cache, and it gives up more quality than the compromise below, which is why it is the less common of the two.
Grouped-query attention (GQA)
The current default
Heads share key and value projections in groups. Cuts the KV cache substantially with little quality loss, which is why nearly every recent open model uses it.
Sliding window
Bounded context per layer
Each token attends only to a nearby span, making cost linear rather than quadratic. Information still travels further by passing up through layers.
Causal masking
Not a variant, a requirement
During generation a token must not see the future, so the upper triangle of the attention matrix is masked out. This is what makes the model autoregressive.
GQA is why long context got affordableThe KV cache scales with the number of key-value heads, not query heads. Sharing them across groups cuts cache memory by a large factor — often four to eight times — with quality differences small enough to be hard to measure. That single architectural change did more for practical long-context serving than any increase in window size, and it is invisible from the outside.

FlashAttention, and why it is not on that list

Everything above changes what attention computes. FlashAttention changes only how, and it is the single most consequential attention result of recent years for anyone actually running a model.

The observation is the one the hardware lesson makes about the whole machine, applied here: the arithmetic was never the bottleneck, the memory traffic was. Standard attention builds the full n-by-n score matrix in the accelerator's main memory, writes it, reads it back for the softmax, writes it again, reads it once more for the weighted sum. For a long sequence that matrix is enormous and every one of those trips crosses the slow gap. FlashAttention never materialises it: it works in tiles small enough to stay in fast on-chip memory, keeps a running softmax as it goes, and recomputes what it needs during the backward pass rather than storing it.

Worth knowing

FlashAttention is exact. It computes the same numbers as standard attention, and the speed comes entirely from moving fewer bytes.

This is what separates it from every other entry in the variants list. Grouped-query attention, sliding windows and sparse patterns all change the function being computed and therefore trade quality for cost, which means they need evaluating. FlashAttention returns the same result and needs no quality re-check — the paper's title says exact for exactly this reason. It is a rearrangement of the memory access pattern, not an approximation, which is why it was adopted everywhere almost immediately and why you are already using it without having chosen it.

For exampleDao and colleagues report a 3× end-to-end speedup on GPT-2 and 15 per cent on BERT-large, with no change to the model or its outputs. The gain is entirely in not writing an intermediate matrix to slow memory and reading it back twice.

The pattern to carry away from this

Three times faster, no quality cost, no change to what the model computes — from noticing that the expensive part was data movement rather than arithmetic. That is the same finding as the memory-bound decode, the same finding as prefix caching, and the same finding behind quantization helping more than pruning. When something is slower than the arithmetic suggests it should be, the answer is nearly always bytes crossing a gap, and the fix is nearly always to move fewer of them rather than to compute less.

Self-attention, cross-attention, and where the queries come from

Everything so far has tokens attending to other tokens in the same sequence, which is self-attention. The machinery does not require that. In cross-attention the queries come from one sequence and the keys and values from another, which is how one representation reads from a different one — a decoder attending to an encoder's output in translation, or a language model attending to the output of an image encoder in a vision-language model. The arithmetic is identical; only the source of the three vectors changes. It is worth knowing because it is the join between modalities: when a model “sees” an image, cross-attention is frequently the mechanism by which the text side reads the vision side.

The alternatives, so the transformer does not look inevitable

Attention won decisively and the search did not stop. Linear attention approximates the softmax so the computation can be reordered into something linear in sequence length rather than quadratic, trading exactness for scaling. State-space models take a different route entirely, carrying a fixed-size recurrent state like the architectures attention displaced, but designed so training still parallelises — which was the thing the old recurrent models could not do. Several current systems are hybrids, interleaving a few full-attention layers among cheaper ones, on the reasoning that you need exact long-range lookup occasionally rather than at every layer. None of this changes what you should learn first; it is here so that a name you meet reads as a live alternative rather than a mystery.
