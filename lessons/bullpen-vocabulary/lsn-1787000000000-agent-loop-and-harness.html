The Agent Loop and the Harness

The two words that appear most often in your own docs — and the difference between them.

Across Bullpen's documentation, agent loop appears 38 times and harness 24. They are the two most-used pieces of vocabulary in the project after the name of a tool. They are also routinely confused, including in your own notes, so start here.

The agent loop is a while-loop

Strip away the branding and an AI agent is a loop that runs until something says stop:

while not done:
    response = model(conversation)
    if response.wants_to_use_a_tool:
        result = run_tool(response.tool_call)
        conversation.append(result)
    else:
        done = True

That is the whole idea. The model cannot do anything — it emits text. When that text is a request to run a tool, something outside the model runs the tool and appends the result to the conversation. Then the model gets another turn. The loop is what turns a text predictor into something that appears to act.

Why this mattersAlmost every agent failure is a loop failure, not a model failure. The loop ran out of turns, or fed back a badly-formatted tool result, or never noticed the model was going in circles. When an agent misbehaves, look at the loop before you blame the model.

The harness is everything around the loop

The harness is the scaffolding: what goes into the prompt, which tools are registered, how results are formatted on the way back, how many turns are allowed, what happens on failure, how the session is persisted. The model is a component the harness calls.

This distinction has a direct consequence you have already recorded. Your own note on Bullpen's multi-file editing wall concluded that the binding constraint is harness, not model size — the models were capable enough; the scaffolding around them was what capped performance at 11 of 24. That conclusion is only expressible if you hold the two terms apart.

The practical ruleIf a bigger model would fix it, it's a model problem. If better prompting, better tool results, or more turns would fix it, it's a harness problem. Most of the time it's the harness — which is good news, because the harness is the part you control.

The word you'll see elsewhere

Outside your codebase, people also use harness to mean an evaluation harness — the rig that runs a model against a test set. Bullpen uses it in both senses, which is a genuine ambiguity rather than your misunderstanding. Context disambiguates: an agent harness runs one task for a user, an eval harness runs many tasks for a score.
