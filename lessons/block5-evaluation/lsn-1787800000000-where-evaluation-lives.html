Where Evaluation Lives

The map. Which artefact answers which question, and the order that stops you wasting a week.

Evaluation in this course is deliberately spread out. The vocabulary sits in Block 0 because you need it before anything else makes sense; the procedure sits in engineering practice because it is a working habit, not a topic; the checklist sits in the standard operating procedures because you run it rather than read it. That distribution is right, and it has one cost: there is no front door. This lesson is the door.

Nothing here is new. If you have read the lessons it points at, you can skip it — and if you have not, reading them in this order will save you the week that reading them in a different order costs.

Four questions, four places

Is my measurement trustworthy?
How to Measure, step 0 — and measurement.md
The fixture must fail before the work and pass after it. If “did nothing” and “solved it” can score the same, every number below is noise. This is the step people skip and the reason most evaluation effort is wasted.
What am I measuring against?
The Eval Battery
A fixed set of tasks with checkable outcomes, held privately, that reflect your work rather than the field's. Also why public benchmarks will not answer your question — contamination, gaming, and task mismatch.
How do serious people do it?
SWE-bench, and How to Actually Run It
A real harness, in detail: what a task actually is, the four variants and which number gets quoted, and what the score does not mean. Read it for the harness design, not the leaderboard.
How do I score something with no right answer?
Models Judging Models, then Rubrics and Blind Reads in this block
The first covers what a judge buys and the four biases it ships with. The second is the two mechanics that make one usable — a rubric careful readers can agree on, and blinding so the score is about the output rather than about what you hoped for.
Why did this number move?
Confounds You Cannot See, and Localising a Failure
The difference between a result and an explanation. A number that moved without a located cause is a number that will move back.
Worth knowing

Evaluation fails at step zero far more often than at the clever parts.

Almost every wasted evaluation effort is a good procedure run on an instrument nobody checked. The fixture passed whatever you did, or failed whatever you did, and the elaborate comparison downstream was measuring the harness. The clever parts — judges, sweeps, statistics — cannot rescue a broken instrument, and they are what people reach for first.

For exampleA set where every model scores identically is not a finding about models. It is a finding about your harness, and reading it as a finding about models has cost teams months.

What this block adds

Two things the material above does not cover. The first is where the labels come from: a battery with indefensible labels measures your opinions rather than the system, and the failure is invisible because everything still runs. The second is comparing across models, where the same set can produce a different ranking depending on a budget you set without thinking about it.

Which tool, when

Six situations, six lessons. This is the fast lookup — read the lesson it names before running the comparison, not instead of it.

Same task, same model, one variable changed
Paired comparison, credible interval
Score each item under both arms and take the per-item difference rather than two separate averages — pairing cancels whatever the pair shares, usually question difficulty. Read the interval width before claiming anything; see Is the Difference Real?
One set, several models
Non-completion column, fixed output budget
The same truncated output budget silently reorders a ranking before any real model difference does. See One Set, Many Models.
No single right answer, free-text output
Rubric plus blind read
A rubric careful readers agree on, scored without seeing which arm produced the answer. See Rubrics and Blind Reads and Models Judging Models.
A published, community-standard harness rather than your own set
Verified split, harness-vs-model attribution
Read it for the harness design, not the leaderboard number — the same model weights can score sixteen points apart depending on scaffolding alone. See SWE-bench, and How to Actually Run It.
Live traffic, real users, unpaired
A/B discipline, the peeking problem
No item appears in both arms, so the comparison needs random assignment and a stopping rule fixed before the data arrives. See Is the Difference Real?.
Multi-turn or agent output
Trajectory scoring
The failure is rarely in the single turn you graded. See Judging a Conversation.

Vocabulary for the comparison itself

Baseline vs candidate
Change off vs. change on
A number with nothing to compare to is a measurement of your setup, not your change. Run the unchanged configuration concurrently, alongside the candidate — a stored number from last month attributes every change since (a model updated under you, a busier machine) to your treatment.
Control fixture
A deliberately easy task in the same harness
When a board reads uniformly zero, a control tells you whether the wall is capability or scaffolding. See Confounds You Cannot See.
Paired vs unpaired
Does the same unit appear in both arms?
An eval on a fixed set is paired by construction; live-traffic A/B is not. Using an unpaired test on paired data can take a real effect from almost always detected to almost never.
Confidence interval vs prediction interval
About the mean vs. about the next case
The first shrinks toward nothing as the sample grows; the second converges on the real spread and stays wide. A per-case promise — a latency budget, a single forecast — needs the second, not the first.
Guardrail metric
What must not get worse
Checked alongside the primary metric, and never allowed to declare success on its own — a faster agent that breaks more builds is not a better agent.
Read the procedure before the tools

How to Measure is six steps and takes ten minutes to read. Every tool in this block is worthless applied out of that order — a judge calibrated against an unproven instrument produces confident, reproducible, wrong numbers.
