Lesson 2 of 12

When the Scaffolding Turns on You

Each of the three artifacts has a characteristic way of becoming actively harmful.

All three artifacts are usually presented as unambiguous goods: write more docs, record more decisions, build more tooling. Each has a specific failure mode, and in each case the harmful version is indistinguishable from the useful version at a glance. That is what makes them worth teaching.

The harness talks to the model, and can lie to it

A harness is usually debugged as though it were ordinary software: does it crash, does it return the right value. But an agent harness has a second output almost nobody audits — everything it says to the model. Tool results, error messages, injected guidance, the prompt itself. All of it is text the model reasons from, and none of it is covered by your tests.

Five defects found in one afternoon in a single production agent harness, none of which failed a test, threw an exception, or appeared in any metric:

“You already read this file”
False
The dedup key was the file path and ignored the requested line range. The model was paging a long file — the only way to read it — and every page after the first was reported as a repeat. It fired 21 times in one run, against 3 firings for every other message combined.
“Before changing code, inspect”
Unsatisfiable
No exit criterion. A compliant model obeys it indefinitely.
“[clipped: original bytes 68671]”
True but unactionable
Tool results were clipped to a character budget, head-only. The read tool put “read again from line N” at the end of its output, so the one actionable sentence was always the first thing cut.
“Its edits are already on disk”
False
Said to the second attempt regardless of whether the first had written anything. When the first wrote nothing, the second opened by hunting for work that never happened — and said so in its reasoning.
“…use search to explore”
True, wrongly placed
Appended last, in the highest-recency position, directly after a message demanding an immediate edit.
The general formNot one of these was a logic bug. Every one was speech — the harness saying something to the model that was false, unsatisfiable, or true-but-useless. If your harness generates text the model reads, that text is part of your system and needs the same scrutiny as a return value.

The sharpest version of this: a harness can suppress a capability the model already has. The failure then looks exactly like a model limitation, and every reasonable next step — a bigger model, more turns, better retrieval — is aimed at the wrong thing.

A recipe with a stale first step is worse than no recipe

A recipe's value is concentrated in its first instruction, because that is the one followed under pressure by someone who does not yet understand the problem. A first step that points the wrong way does not merely waste time; it lends institutional authority to the wrong hypothesis.

A real triage table entry read: “Model reads forever, never edits → count reads versus edits → the lever is the read budget.” Four sections below, the same document listed that budget as its own worst tarpit — eleven separate commits of tuning it, with a stated lesson that tuning it for one model breaks another. The recipe was sending every reader straight to the lever the document itself said not to reach for.

The asymmetryA missing runbook makes you think. A confidently wrong runbook makes you stop thinking, at exactly the moment you were about to. Audit the first step of every recipe you own more often than the rest of it.

ADRs ossify

An ADR records a decision and the evidence that forced it. The decision persists in the document; the evidence decays in the world. When the two separate, the ADR becomes a rule enforced past its reason — and because it is written down and was once correct, it is unusually hard to argue with.

One agent project spent months describing itself as a cascader: a system that tries a local model and escalates to progressively larger ones. That was a genuine, well-reasoned decision. Measurement later falsified the premise it rested on, and the project became a local agent that occasionally escalates. The architecture docs kept saying cascader, so new work kept being designed against a system that no longer existed.

Retrospective justification
The common one
An ADR written after the fact to legitimise a choice already made. It reads identically to a real one and contains no decision.
Consequence amnesia
The costly one
The “consequences” section is where an ADR states what it is giving up. Teams write it, then never re-read it when that cost starts being paid.
Status theatre
The wasteful one
Every change gets an ADR, so nothing is signal. If it does not forbid a sensible-looking future change, it is not a decision.

The unifying diagnosis

All three failures share a shape: an artifact that was true when written, still asserting itself after its truth expired. The harness message that was accurate before the file grew. The recipe step that was right before the lever was exhausted. The ADR that was correct before the measurement came back.

Which is why none of the three is self-correcting, and why the next lesson is about the only thing that corrects them.

The size of the harness effect, measured

This is usually asserted and rarely quantified, so here it is with numbers. SWE-bench Verified is 500 real GitHub issues. These five submissions all run the same model — claude-3-5-sonnet-20241022 — and differ only in the scaffolding around it:

What this licenses you to sayA sixteen-point spread on identical model weights. If you swapped models and saw a gain that size you would call it a generational leap — here it is entirely scaffolding. Note also AutoCodeRover v2.0 to v2.1: the same team, the same model, 231 tasks to 258, from harness work alone. When something underperforms, the harness is the higher-yield place to look, and this is the evidence for it rather than the intuition.
Read it carefully, thoughThese submissions differ in more than scaffold — different prompts, retrieval, retry budgets and token spend. The spread is an upper bound on what harness work can buy, not a controlled experiment. It tells you the harness matters enormously; it does not tell you which harness change is responsible. That distinction is the whole of the next two lessons.
