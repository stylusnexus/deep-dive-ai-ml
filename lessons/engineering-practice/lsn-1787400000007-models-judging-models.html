Lesson 8 of 11

Models Judging Models

LLM-as-judge — what it genuinely buys you, the four biases it ships with, and the failure that manufactures results.

Deterministic grading is the top of the ladder and most interesting outputs don't have it. Summaries, explanations, tone, helpfulness, whether an answer is grounded in its sources — none compiles, none has a test suite. The pragmatic answer is to have another model grade it, and that answer is genuinely useful and genuinely dangerous in ways worth knowing precisely.

What it buys you

Coverage
Grades what nothing else can
Open-ended text, where the alternative is no measurement at all rather than a better one.
Scale
Hundreds of items, minutes, pennies
Human labelling of the same set is days and real money.
Consistency
Same rubric every time
Human raters drift across a long session; a judge at temperature 0 does not.
Structure
Rubric dimensions, not one score
Groundedness, completeness and tone as separate numbers, which a single human score usually blurs.
Iteration speed
The real win
A judge you can run in ninety seconds changes how often you measure, and frequency of measurement matters more than precision of any single run.

The four biases it ships with

These are documented, reproducible, and present by default. Treat them as properties of the instrument rather than as bugs to be prompted away.

Position bias
Order changes the verdict
Present the same two answers in the opposite order and judges flip a substantial fraction of their decisions. Mitigate by running both orders and discarding disagreements — or counting them as ties.
Verbosity bias
Longer reads as better
A judge rewards length beyond the point where length helps. If one of your variants is chattier, you will measure that.
Self-preference
Models favour their own output
Evaluators recognise and prefer their own generations. A judge from the same family as the system under test is not neutral.
Score compression
Everything is a 7 or 8
Absolute 1–10 scoring clusters hard. Pairwise comparison discriminates far better than asking for a number.
Circularity is the version that voids the result entirelyIf the judge is the model under test, you are asking a system to score itself and the number carries no information about capability. The softer version is subtler and far more common: judging with a model from the same family, trained on overlapping data, sharing the same blind spots. It will not notice the errors it would have made itself — which are exactly the errors you most need to catch.

The failure that manufactures results

The biases above add noise, and noise is survivable. There is a worse case, and it is easy to walk into.

On one project an automated flag called edit_attempted was used as a measurement. It had been built as a safety classifier, and it counted certain shell commands as evidence of an edit attempt. About 15% of the recorded attempts had no edit tool call behind them at all.

That alone is tolerable — a known error rate can be corrected for. The problem was that the error was not uniform across conditions. The experimental condition relaxed budgets, which meant it ran more shell commands, which meant it accumulated more phantom credits. The difference between conditions was partly a measurement of shell activity rather than of editing.

Ask this before trusting any judge comparisonNot "how accurate is the judge?" but "is the judge's error correlated with the thing I changed?" If one variant produces longer answers and your judge rewards length, you have a verbosity bias masquerading as an improvement. If one variant is more verbose because it explains itself more, you cannot tell those apart from the score alone. Extra samples will not save you — bias does not average out.

A judge that is silently off is worse than no judge

On the same project, one configuration default meant the verifier was nil. That single value disabled turn-end verification, the fix-attempt loop and per-edit feedback simultaneously — and nothing said so. The system continued producing results that looked like verified results.

No judge at all is an obvious gap. A judge that has quietly stopped running is a number that carries authority it has not earned. Assert that your grader ran, on every run, and fail loudly when it did not.

How to use one properly

Last resort on the ladder
Not first reach
Deterministic, then reference-match, then judge. Every rung down costs certainty.
Different family from the system
Avoid self-preference
And never the model under test.
Pairwise, not absolute
Discriminates far better
"Which is better" beats "score this 1-10", which clusters.
Both orders, every time
Neutralises position bias
Disagreement between orders is a tie, and its rate is a health metric for your judge.
Calibrate against humans
The step nobody does
Label 30-50 items by hand once. Measure agreement. If the judge disagrees with you on the cases you care about, it is not measuring what you think.
Report agreement alongside scores
Honesty about the instrument
A judge score without a known agreement rate is an opinion with a decimal point.
When you can buy a deterministic verifier, buy itOne agent project verifies its edits with typecheckers and a language server rather than a model judge. That is narrower than a judge and it is not an opinion, which is what a loop needs when the verdict decides whether to escalate. Reach for a judge where nothing checkable exists — not because it was quicker to build than a real check.

Where this connects

This is the same principle as the loops lesson, one level up: a loop or a score improves things only when signal enters from outside. A judge from the same family as the system under test is not outside. A grader whose error tracks your treatment is not outside. Human labels, a compiler, a test suite and a held-out answer key are.

Further reading

  • Judging LLM-as-a-Judge (Zheng et al., 2023)The MT-Bench paper. Documents position, verbosity and self-enhancement bias, and reports agreement rates against human raters.
  • LLMs are not Fair Evaluators (Wang et al., 2023)Position bias in detail, and the swap-and-compare mitigation used above.
  • LLM Evaluators Recognize and Favor Their Own Generations (Panickssery et al., 2024)Self-preference measured directly. The reason a judge from the same family as the system under test is not neutral.
