Lesson 10 of 14

Code Nobody Decided

The previous lesson asked whether to use a model. This one asks who chose the behaviour when you did.

A pull request looks good. Clean structure, real error handling, sensible names, tests passing, and it matches the API contract. The reviewer approves it and moves on. Three weeks later the on-call engineer is paged: the endpoint returns a conflict for cancelled orders. The product team is baffled — they never asked for that. The engineer who raised the pull request cannot explain where the rule came from either. She prompted for the endpoint, read the output, thought it looked reasonable, and shipped it.

Nothing here is broken. The code works exactly as written. What went wrong is that nobody chose this behaviour, and the team is now maintaining business logic that arrived by autocomplete. That failure has no error message, no failing test and no bad reviewer. It has a three-week delay and somebody else's pager.

Why review stops working

Reviewing code and reviewing decisions are different activities, and generated code makes them easy to confuse. When a person writes something unusual, the oddity is a signal — they had a reason, and the reviewer asks about it. When a model writes something unusual, the oddity means nothing at all, because there was no reason. It was a plausible continuation.

So the reviewer's usual instrument stops reading. Approving output that looks correct is not the same as approving a decision, and if there is no decision underneath, review has quietly become proofreading. The output arrives with the surface features of considered work — structure, handled edge cases, tests — and none of the substance.

Decided behaviour
Someone can say why
A person chose it, for a reason that survives being asked about, and the reason is recoverable later from a specification, a decision record or a commit message.
Invented behaviour
Plausible, and unowned
It appeared because it was a likely continuation. It may be sensible. Nobody weighed it, nobody can defend it, and nobody knows what it was trading off.
The delay
Weeks, and it lands on someone else
Invented behaviour is not detected at review, because it looks like the rest. It is detected in production by whoever is on call, which is the most expensive place and the least equipped person.
Worth knowing

Generated code arrives with the appearance of considered work and none of the substance.

Structure, error handling, naming and tests are the signals a reviewer uses to judge whether someone thought carefully. A model produces all of them regardless of whether anything was thought about, so the correlation those signals rely on is broken. This is why AI-assisted review degrades into rubber-stamping without anyone deciding to lower their standards — the instrument stopped measuring what it used to measure, and nothing announced it.

For exampleThe practical test is not “is this code good” but “can anyone say why it does this?” Ask it of any behaviour a specification did not require. If the answer is that it looked reasonable, the behaviour is unowned, whatever its quality.

What actually helps

  • Prompt for the decision, not the implementation. Asking for options with trade-offs produces something to choose between; asking for the endpoint produces something to accept. The first leaves a decision in the transcript, the second leaves an artefact.
  • Write the intent before the code exists. The specification lesson that follows is this in practice, and its value here is specifically that it gives review something to check the diff against.
  • Review behaviour, not lines. The question is what this now does that it did not do before, and whether anyone asked for each of those things.
  • Treat unexplained behaviour as a defect. Not necessarily wrong — unowned. A behaviour nobody can justify is one nobody can safely change either, which is how it survives to become load-bearing.
The cost is deferred, which is why it accumulates

Nothing punishes you at the moment this happens. The code works, the tests pass, the feature ships and the sprint looks good. The bill arrives later as a codebase whose behaviour nobody can account for, one plausible addition at a time — and by then the person who could have explained any single piece has long moved on to the next ticket.
