Drift: Why Deployment Isn't the End

The model didn't change. The world did.

A model deployed in March performs beautifully. By September it's noticeably worse, and nobody has touched it. Nothing broke — the world moved and the model didn't. This is drift, and it's why deployment is the start of a model's life rather than the finish.

Two kinds, with different fixes

Data drift
The inputs change
New customer demographics, a new sensor with different calibration, seasonal shifts. The relationship between input and output still holds — you're just seeing inputs the model wasn't trained on.
Concept drift
The relationship changes
What counted as fraud last year doesn't this year, because fraudsters adapted. The same input now maps to a different correct output. Harder, and retraining on recent data is the only real answer.
Why the distinction pays offData drift often needs nothing more than retraining on recent data, or sometimes just recalibration. Concept drift means your labels have changed meaning — historical training data is now actively misleading, and you may need to discard or reweight it. Diagnosing which one you have decides whether you retrain on everything or only on what's recent.

How you actually detect it

The awkward part of drift is that the thing you want to watch — whether predictions are still correct — needs labels, and labels arrive late or never. So detection works on what you do have, which is the inputs and the outputs, and the methods form a ladder from cheap to thorough.

Summary statistics per feature
Cheapest, and catches the obvious
Mean, spread, missing rate and category frequencies, compared against the training distribution. Finds the breakages that matter most often: a unit change, a new category, a feed that started sending nulls.
Distribution tests and distances
One feature at a time, more sensitive
A two-sample test or a distance measure between the training and recent distributions of each feature. More sensitive than summary statistics, and it will find differences too small to matter, so it needs a threshold you chose deliberately.
A domain classifier
The trick worth knowing
Label training data 0 and recent data 1, and train a classifier to tell them apart. If it cannot, the distributions match. If it can, its accuracy measures how much they differ and its feature importances tell you which features moved.
Output monitoring
What to watch when inputs look fine
The distribution of the model's own predictions. A classifier that used to predict the rare class two per cent of the time and now predicts it nine per cent is telling you something before any label arrives.
Worth knowing

The domain classifier is the one to reach for, because it answers the multivariate question the per-feature checks cannot.

Features can drift jointly while every one of them looks unchanged on its own. Height and weight can each keep their exact distribution while the relationship between them inverts, and no per-feature test will see it because no single feature moved. A classifier trained to separate old data from new is looking at all the features together, which is why it catches the joint case — and it costs you a model you already know how to build.

For exampleEvery feature in a fraud model passes its individual distribution test. A domain classifier separates last month's traffic from the training set with 89 per cent accuracy, and its top features are transaction amount and time of day — neither of which shifted alone, but whose combination did. The fraud pattern had changed shape without changing any margin.

Detection is not the hard part; deciding the threshold is

These methods will all report some drift all the time, because distributions are never identical between two windows. A detector with no threshold produces an alert stream nobody reads, which is the failure mode the telemetry lesson describes: a signal that fires constantly conveys nothing. Set the threshold against a period you know was healthy, and pair the alert with the action it should trigger — retrain, investigate, or record and move on. An alert with no attached decision is a notification, not monitoring.

The monitoring problem

You usually can't measure accuracy in production, because ground truth arrives late or never. Whether a loan defaults takes months. Whether a maintenance prediction was right takes until the part fails or doesn't. So you monitor proxies that are available immediately:

  • Input distributions. Are the features arriving now shaped like the training data? Population Stability Index, or a KS test per feature.
  • Prediction distribution. Your fraud model flagged 2% for six months and now flags 7%. Something changed, even if you don't yet know what.
  • Confidence distribution. Predictions clustering near the threshold instead of the extremes means the model is less sure than it was.
  • Delayed ground truth. When labels do arrive, backfill and score properly. Late is still worth having.
  • Data quality. Null rates, new categorical values, unit changes. An upstream team renaming a field looks exactly like drift and is far more common.
The most common cause isn't drift at allBefore concluding the world changed, check whether an upstream pipeline changed. A schema alteration, a unit switch from Celsius to Fahrenheit, a newly-added category, a join that silently started dropping rows — these produce identical symptoms and are much more likely. Check the data before retraining the model.

Drift for generative systems

The concept transfers, in forms specific to LLM work: your provider silently updates the model behind a version alias and outputs change; your retrieval corpus grows and previously-reliable chunks stop ranking; users learn what the system does well and ask harder questions over time. Pin model versions where you can, and re-run your eval set on a schedule rather than only when something looks wrong.

What to build

A monitored model needs a baseline snapshot of training-input distributions, scheduled comparison against live traffic, alert thresholds that someone actually receives, a retraining path that can be executed without heroics, and a rollback. Block 8 builds this, because a model you can't retrain safely is one you'll be afraid to touch precisely when you need to.
