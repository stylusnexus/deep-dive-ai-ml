The Agent Loop and the Harness

The two words that appear most often in your own docs — and the difference between them.

Agent loop and harness are the two most-used words in any agent codebase, and two of the most routinely confused. Separating them is worth doing first, because almost every diagnosis later in this course depends on the distinction.

The agent loop is a while-loop

Strip away the branding and an AI agent is a loop that runs until something says stop:

while not done:
    response = model(conversation)
    if response.wants_to_use_a_tool:
        result = run_tool(response.tool_call)
        conversation.append(result)
    else:
        done = True

That is the whole idea. The model cannot do anything — it emits text. When that text is a request to run a tool, something outside the model runs the tool and appends the result to the conversation. Then the model gets another turn. The loop is what turns a text predictor into something that appears to act.

Why this mattersAlmost every agent failure is a loop failure, not a model failure. The loop ran out of turns, or fed back a badly-formatted tool result, or never noticed the model was going in circles. When an agent misbehaves, look at the loop before you blame the model.

The harness is everything around the loop

The harness is the scaffolding: what goes into the prompt, which tools are registered, how results are formatted on the way back, how many turns are allowed, what happens on failure, how the session is persisted. The model is a component the harness calls.

The distinction has a direct diagnostic consequence. One coding-agent project spent months attributing a multi-file editing failure to model capability, then established that the binding constraint was the harness, not model size — the models were capable enough, and the scaffolding around them was what capped the score. That conclusion is not even expressible unless you hold the two terms apart.

The practical ruleIf a bigger model would fix it, it's a model problem. If better prompting, better tool results, or more turns would fix it, it's a harness problem. Most of the time it's the harness — which is good news, because the harness is the part you control.

The loop, end to end

1
A request arrives
The interface hands it to the harness.
2
The harness assembles context
System prompt, session history, retrieved repo context, available tool definitions.
3
The loop starts
Model responds. Wants a tool? Run it, append the result, go again.
4
The loop ends
Model answers without requesting a tool, or hits the turn limit, or escalates.
5
The harness persists
Session and memory are written down so the next turn has history.
Worth knowing

If a bigger model would fix it, it is a model problem. If better prompting, better tool results or more turns would fix it, it is a harness problem.

The distinction matters because it decides where you spend. Model problems are expensive and often out of your hands; harness problems are cheap and entirely yours. Most of the time it is the harness, which is good news.

For exampleAn agent reads the failing tests, derives the correct fix, names the insertion point — then asks to read one more file. Every run. Nine scaffolding changes moved nothing. The prompt said to inspect before editing, which has no exit criterion, so a compliant model complied forever. The fix was one sentence, not a bigger model.

The word you'll see elsewhere

Harness is also used for an evaluation harness — the rig that runs a model against a test set. Most projects use it in both senses, which is a real ambiguity in the field rather than a misunderstanding on your part. Context disambiguates: an agent harness runs one task for a user, an eval harness runs many tasks for a score.

1. An agent gets stuck repeating the same tool call five times before giving up. Where is the problem most likely to be?

The model isn't large enough and should be swapped for a frontier model
The harness — nothing is detecting the repetition or feeding back that the approach isn't working
The tool itself is broken and returning errors

2. What is the one thing a language model fundamentally cannot do inside an agent loop?

Produce structured output like JSON
Decide which tool would be useful
Actually execute a tool — it can only emit a request that something else runs

3. A project concludes its multi-file failure was harness, not model size. What would the alternative conclusion have been?

That the models lacked the capability, and only a bigger model would move the number
That the tools were badly written
That the test itself was measuring the wrong thing
