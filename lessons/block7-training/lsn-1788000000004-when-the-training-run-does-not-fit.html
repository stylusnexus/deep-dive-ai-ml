When the Training Run Does Not Fit

Three techniques that trade time or precision for memory — and the order to reach for them.

The commonest failure of a first training run is not a bad result. It is an out-of-memory error thirty seconds in, and the instinct it produces — use a smaller model — is usually the wrong response, because the memory is going somewhere you can control.

Where the memory actually goes

Four things are resident during training and only the first is the model. The weights themselves; the gradients, which are the same size again; the optimiser state, which for the common choice of optimiser is roughly twice the weights once more; and the activations, which are the intermediate values from the forward pass that the backward pass needs in order to compute anything at all.

The proportions surprise people. For a large model with a short sequence, the first three dominate and the arithmetic is fixed. With a long sequence or a large batch, activations grow until they are the largest single item — and unlike the other three, activations scale with what you feed the model rather than with how big it is.

The three levers

Mixed precision
Store in half, accumulate in full
Hold weights and activations in a sixteen-bit format while keeping a full-precision copy of the weights for the update. Roughly halves memory and is usually faster as well, because moving fewer bytes is the thing that helps on memory-bound hardware.
Gradient accumulation
A large batch, taken in instalments
Run several small batches, add up their gradients, and update once. The maths is the large batch; the memory is the small one. It costs no accuracy and it costs wall-clock time, since you have done the same forward passes without the parallelism.
Gradient checkpointing
Throw activations away and recompute them
Keep only a few activations from the forward pass and recompute the rest during the backward pass. A large reduction in activation memory in exchange for running part of the forward pass twice. The time cost is real and worth measuring on your own run rather than assuming, since it depends on how much gets recomputed and on how memory-bound the step already was.
The order to try them
Cheapest concession first
Mixed precision, then accumulation, then checkpointing. The first often costs nothing at all, the second costs time, the third costs more time. Reach for a smaller model only after all three.
Worth knowing

Two of these three cost time and none of them cost accuracy. That is why reaching for a smaller model first is usually the wrong move.

Accumulation is arithmetically identical to the large batch it imitates, and checkpointing recomputes exactly the values it discarded, so neither changes the result of the run — only how long it takes. Mixed precision is the one that touches numerics, and the full-precision master copy of the weights exists precisely so that the update does not lose the small increments that matter. A smaller model, by contrast, changes what you are able to learn, which is the one concession that shows up in the evaluation.

For exampleA run fails at a batch size of 16 on a 13-billion-parameter model. Mixed precision alone brings it within reach; if it does not, four accumulation steps at a batch of 4 give the same gradient as the batch of 16 at a quarter of the activation memory, and the only cost is that the epoch takes longer. Neither of those changes a single number in the final evaluation.

The failure that looks like the technique and is not

Sixteen-bit formats have a much narrower range than thirty-two-bit ones, and gradients are small numbers. In the older half-precision format they can underflow to zero, at which point training quietly stops learning — the loss flattens and nothing errors. The standard remedy is loss scaling: multiply the loss before the backward pass to lift the gradients into representable range, then divide it out before the update. Modern frameworks do this for you, and the newer sixteen-bit format designed for machine learning trades precision for range specifically to avoid the problem.

The reason to know this anyway is diagnostic. A flat loss curve immediately after enabling mixed precision is a numerics problem, not a learning-rate problem, and it will absorb an afternoon if you attack it as the latter.

What none of them fix

These are memory techniques, and the hardware lesson's first rule still governs: capacity is a hard wall and library support is what actually blocks people. A sixteen-bit format that has no implementation on your accelerator will fall back to something slower or fail outright, and no amount of accumulation makes a model fit that was never going to. Check that it fits, then check that the operations you need exist, and only then start trading time for room.
