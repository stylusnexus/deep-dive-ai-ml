# Runs behind the numbers in the quantization lessons and notebook

Recorded 2026-10-02 with `scripts/measure_quantization.py`. Perplexity, KL divergence and top-1
agreement do not depend on how busy the machine is, so unlike the serving runs these repeat exactly:
the notebook's table was produced twice, in two executions a few minutes apart, with identical figures.

- Machine: Apple M4 Max, 128 GB. mlx-lm 0.31.3 (Python 3.11 uv tool), mlx 0.31.2. llama.cpp build 10360, `llama-quantize` only (no `llama-perplexity`, no `llama-imatrix` in this build).
- Text: the 11 documents in `data/corpus/` (generated by `scripts/make_corpus.py`), 8 windows of 512 tokens = 4,088 scored tokens. No model here was calibrated on it.
- GPU use was kept to short bursts because another benchmark was running on the machine: the notebook ran 10:57:43 to 10:58:55 and 10:59:33 to 11:00:31, and the Qwen3 scoring below ran 11:00:49 to 11:01:44, local time.

The DWQ file is better than plain rounding on perplexity and top-1 agreement and worse on KL divergence.
The three model cards (read 2026-10-02) are word for word the same apart from the name: "converted to MLX format
from Qwen/Qwen3-0.6B using mlx-lm version 0.24.0". They name no recipe and no calibration data.

## Failed attempt, kept for honesty
`mlx_lm.dwq --model Qwen/Qwen2.5-0.5B-Instruct --bits 3 --group-size 64 --num-samples 128 ...` failed at once with
`ModuleNotFoundError: No module named 'datasets'`: DWQ needs the `mlx-lm[train]` extra. It was not rerun, so no DWQ
figure in the lessons is from our own DWQ run. A CPU-only evaluation of the 0.5B model was also tried and abandoned
after about seven minutes without finishing a two-window pass.
