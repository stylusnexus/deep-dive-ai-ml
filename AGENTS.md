# AGENTS.md — Building and Measuring LLM Systems

Instructions for any coding agent working in this repository. Written to be read
cold, without the conversation that produced the repo.

See [`CLAUDE.md`](CLAUDE.md) for the full architecture. This file is the short
version plus the things agents specifically get wrong here.

## What you are working on

A self-built applied AI/ML curriculum: 63 lessons, 8 notebooks, 2
projects, 10 SOP checklists. The reader is one person learning this material
properly, not a class. Tone is direct and evidence-first.

## The single most important rule

**Lessons in `lessons/` are generated. Never edit them.**

Edit `scripts/content/<module>.py`, then:

```bash
python3 scripts/build_lessons.py <module>
python3 scripts/build_index.py
python3 scripts/build_knows.py
```

An edit to a generated HTML file will be silently destroyed on the next build,
and you will have wasted the work without any error telling you so.

## The second most important rule

**Notebooks must be committed with their executed outputs.**

`scripts/build_notebooks.py` regenerates notebooks *without* outputs. If you
rebuild, you must re-execute before committing:

```bash
jupyter nbconvert --to notebook --execute --inplace <file>.ipynb
```

This has been got wrong twice in this repo's history. A notebook without outputs
is a claim nobody has checked.

## Evidence standards

This repo holds a higher bar than most. Before you assert something in a lesson:

- **Numbers come from runs.** If you write "roughly 85% fewer tokens", it came
  from a source you read, and you cite it. If you write "0.343 average
  precision", you ran it.
- **Links are verified.** `curl -sL -o /dev/null -w "%{http_code}"` before commit.
  Two known exceptions bot-block (MIT Press, OpenAI) and are real pages.
- **Claims about the machine are measured.** Hardware, backends, versions — check
  rather than assume. The course teaches this; the repo must practise it.
- **When a result is an artefact of your setup, fix it and say so.** Two results
  in Block 2 were wrong for that reason and the commit messages explain both.

## Content conventions

- Every lesson carries at least one inline SVG diagram
- Every acronym expands on first use **within each lesson** — they are read standalone
- `know` blocks are three parts: rule, why, worked example. Never just a rule
- Examples are specific and named, never "a model might..."
- British spelling, and no em-dash-heavy prose
- Do not create planning or summary markdown files unless asked

## Validation before commit

Run this. It has caught real defects:

```python
# SVG well-formed, no literal \uXXXX escapes, no backticks outside <script>,
# every know block complete, every lesson has a diagram
```

The builder itself asserts on undefined callout variants and backticks in quiz
text. If a build fails with an assertion, the content is wrong, not the builder.

## Known traps

| trap | symptom | fix |
|---|---|---|
| Heredoc escaping | `—` renders literally | use real characters, not escapes |
| Backtick in quiz text | build assertion fails | quiz strings are escaped; use plain text |
| Rebuild strips outputs | notebook ships unrun | re-execute after every rebuild |
| Rebuild strips *sibling* outputs | editing one notebook's content wipes all notebooks in that module | if the sibling's source is unchanged, `git checkout HEAD -- <file>` instead of re-running |
| `models[0]` from /v1/models | HTTP 400 on chat completion | filter out embed/rerank/whisper models — the first listed is not necessarily a chat model |
| `max_tokens` too low for a reasoning model | empty answer, scored as wrong — or a fabricated `NOT IN CONTEXT` | reasoning burns the budget before the first visible word; check `finish_reason == "length"` and record it. ~850 completion tokens is the worst case on this corpus, so the ceiling is 1500 |
| `None` groundedness in a pandas column | refusals silently labelled as ungrounded answers | `None` becomes `NaN`; test with `pd.isna(x)`, never `x is None` |
| `pd.Timedelta(days=n)` | DeprecationWarning under numpy 2.5 | `np.timedelta64(n, "D")` |
| Suffix filters | duplicate column | name derived features distinctly |
| Hardcoded topic lists | a whole block silently excluded | enumerate directories |

## Environment

Host is Python 3.14 with torch and MPS. Notebooks need 3.12 — TensorFlow has no
3.14 support. Containers are CPU-only on macOS and exist for reproducibility, not
speed. Training runs on the host.

```bash
make check     # verifies python, torch/MPS, docker memory, HF auth, API keys
make up        # torch, keras, pgvector, mlflow
```

Data is generated by seeded scripts in `scripts/`. Nothing large is committed.

`notebooks/04-agentic/02-graph-and-checkpoints.ipynb` needs `langgraph` — the only
framework dependency in the repository, and deliberately confined to the one
notebook whose subject is the framework. Checked against 1.x; `MemorySaver` ships
with it, durable savers (SQLite, Postgres) are separate packages.

## Scope discipline

Build what was asked. If you notice a real problem outside the scope, finish the
task and name the problem in one line at the end — do not fix it, and do not
expand the work because it seemed related.

## Postscript: this happened while writing this file

Notebook `03-grounded-answers.ipynb` was committed with zero outputs, because a
long-running execution was still in flight when `git add -A` ran. The rule two
sections above was written in the same session that broke it.

The lesson is not "be careful". It is that `git add -A` while a background job
is writing to the tree will commit whatever state that file happens to be in.
Check before committing:

```bash
python3 -c "
import json,pathlib
for f in pathlib.Path('notebooks').rglob('*.ipynb'):
    nb=json.loads(f.read_text())
    n=sum(1 for c in nb['cells'] for o in c.get('outputs',[]))
    print(('OK  ' if n else 'UNRUN'), n, f)
"
```
