# Block 3 · Retrieval and Agentic RAG

Runs on `data/corpus/`, generated by `scripts/make_corpus.py`. The corpus is
synthetic deliberately - every fact lives in exactly one document, so the gold
labels in `data/corpus_eval.json` are genuinely correct rather than estimated.
That is what makes recall@k a measurement rather than an impression.

| Notebook | What it does |
|---|---|
| `01-chunking-and-embedding.ipynb` | Fixed-size vs structural chunking, read side by side; embed; load into pgvector with an HNSW index |
| `02-retrieval-quality.ipynb` | Dense, BM25, hybrid and reranked - measured against gold labels; index recall vs exact search across `ef_search` |
| `03-grounded-answers.ipynb` | Generation with citations, groundedness measured separately from correctness, and the refusal test |

## Requirements

The embedding and reranking models download once (~120MB total) and then run
offline. pgvector needs the container:

```bash
docker compose -f docker/compose.yaml up -d pgvector
```

Notebook 03 uses any OpenAI-compatible local endpoint (LM Studio on :11455,
Ollama on :11434). If none is reachable - or a call times out - it falls back to
an extractive stand-in per call and says so. The measurement is the lesson, not
the prose quality of the answers.

## The result that matters

The eval set contains three multi-hop questions whose answers require facts from
two documents. No single-shot retrieval strategy reliably fetches both, because
the question embeds close to one and not the other.

That is not a tuning problem. It is the limit that agentic retrieval exists to
address, and seeing it measured is the point of notebook 02.

## What notebook 03 produced

The diagnosis table populated all four cells on a ten-question set, which is
unusually clean for a teaching artefact:

| diagnosis | count |
|---|---|
| grounded + correct | 4 |
| grounded + **wrong** → retrieval problem | 3 |
| ungrounded + wrong → generation problem | 2 |
| ungrounded + **right** → answering from memory (warning) | 1 |

The three in row two are the multi-hop questions. The model faithfully used what
it was given and was given only half of what it needed - which is what the
lesson means by *grounded and wrong is a retrieval problem*.

The refusal test passes. Note what the output shows: retrieval still returned
four chunks, because similarity is relative and something always comes back. The
refusal came entirely from the prompt handling the empty case.

Five of ten generation calls fell back to the extractive stand-in on a timeout,
which the notebook reports. The measurement is unaffected; the prose of those
answers is extractive rather than generated.
