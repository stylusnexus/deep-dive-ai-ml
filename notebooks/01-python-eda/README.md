# Block 1 · Python, Data and EDA

Four notebooks, run in order. They work on `data/turbine_readings.csv` - a
deliberately messy dataset generated by `scripts/make_dataset.py` (seeded, so
everyone gets the same mess).

| Notebook | What it does |
|---|---|
| `01-first-contact.ipynb` | Survey, don't fix. Finds the leaking feature, the duplicates, the class balance, the string column |
| `02-cleaning-decisions.ipynb` | Each cleaning step as a defensible decision, including the Fahrenheit sites and the MNAR vibration gaps |
| `03-exploring-distributions.ipynb` | Five questions with decisions attached, each answered by one chart |
| `04-split-and-pipeline.ipynb` | Split before fitting, leakage-safe pipeline, and a threshold decision table |

## What's wrong with the data, on purpose

Missing values under three different mechanisms · two sites reporting Fahrenheit in
a Celsius-named column · sentinel values of 9999.0 · thousands separators and stray
units in a numeric column · exact duplicates and re-logged turbines · inspector names
entered four ways · a 15% positive class · one leaking feature.

## Running

```bash
make torch          # Jupyter at localhost:8888
```

All four execute end to end with no manual steps. Read the prose - the code is the
smaller half of each notebook.

**Exit criterion:** a clean EDA notebook on a dataset nobody handed you pre-cleaned,
ending in a threshold table you could defend to an operations manager.
