# CLAUDE.md — `pgp-aiml`

A self-built recreation of the UT Austin / McCombs PGP in AI & Machine Learning,
rebuilt as ~13 weeks of lessons, runnable notebooks and portfolio projects — with
the security, evaluation, cost and fine-tuning material the original omits.

**Read [`CURRICULUM.md`](CURRICULUM.md) first.** It is the map and the status board.

## What this repo is

Not a course *about* AI written by reading other courses. Every claim that can be
checked has been checked, and the checking is visible in the artefacts:

- Notebooks ship **with their executed outputs**, because a notebook that has not
  been run is a hypothesis
- Every external link is verified resolving before commit
- Numbers in lessons come from runs, not from memory (the SWE-bench harness
  spread, the Keras backend loss difference, the random-versus-time split gap)
- Where a result was an artefact of the setup, it was fixed and the fix explained
  rather than shipped quietly

If you change a lesson, hold that standard.

## Layout

```
lessons/          Self-contained HTML lessons, one directory per set
  orientation/        the map, and what is inside an LLM
  core-vocabulary/    the terms every LLM system uses
  algorithms/         what each algorithm does and where it breaks
  engineering-practice/  harnesses, measurement, judging, spec-driven work
  block1-data-eda/    Block 1
  block2-classical-ml/ Block 2
  block3-retrieval/   Block 3
notebooks/        Runnable labs, one directory per block
projects/         Portfolio projects, each a script rather than a notebook
artifacts/        The intake sheet, selection scorecard, and SOP checklists
scripts/          Builders and data generators — content lives here, not in HTML
data/             Generated datasets and corpora (seeded, reproducible)
docker/           Torch, Keras, pgvector and MLflow environments
```

## How to change content — this matters

**Never edit a file in `lessons/`.** They are generated. Edit the content module
in `scripts/content/` and rebuild:

```bash
python3 scripts/build_lessons.py <module_name>   # e.g. core_vocabulary
python3 scripts/build_index.py                   # landing page
python3 scripts/build_knows.py                   # Things to Know revision sheet
```

Notebooks are the same: authored in `scripts/content/*_notebooks.py`, built with
`scripts/build_notebooks.py`, then **executed** so their outputs are committed.

## The block types

Lesson content is a list of tuples. Available blocks:

| block | shape | use |
|---|---|---|
| `p`, `h2`, `h3` | `("p", "html string")` | prose; raw HTML permitted |
| `ul` | `("ul", ["item", ...])` | bullets |
| `code` | `("code", "text")` | escaped, no highlighting |
| `terms` | `("terms", [(label, headline, detail), ...])` | the definition grid |
| `callout` | `("callout", variant, label, html)` | `insight` / `matters` / `pitfall` / `warning` |
| `know` | `("know", rule, why, example)` | pull-quote; harvested into the revision sheet |
| `figure` | `("figure", caption, svg)` | inline SVG diagram |
| `links` | `("links", [(title, url, note), ...])` | verified external sources |
| `books` | `("books", [(title, author, note), ...])` | titles in the local library |
| `quiz` | `("quiz", [(q, [opts], answer_index), ...])` | 3–4 questions |

The builder asserts on undefined callout variants and on backticks in quiz text
(quiz strings are HTML-escaped, so markdown does not render there).

## House rules for content

- **Every lesson carries at least one diagram.** Inline SVG, using the `d-box`,
  `d-label`, `d-fill-*` classes so it works in both themes.
- **Every acronym expands on first use, in every lesson.** Lessons are read
  standalone, not in order.
- **`know` blocks are rule → why → worked example.** A rule alone is a slogan.
- **Examples are specific.** Not "a model might hallucinate" but a named failure
  with numbers.
- **Cite what you assert.** Verify the link resolves before committing it.
- **No third-party runtime dependencies** where the standard library will do.

## Verifying before you commit

```bash
make check                      # environment: python, torch/MPS, docker, HF auth
python3 scripts/build_lessons.py <module> && python3 scripts/build_index.py
```

And the validation the repo has been held to throughout — SVG well-formedness,
no literal unicode escapes, no stray backticks, every `know` block complete, and
every link resolving. See the git history for the exact checks; they have caught
real defects including three unstyled callouts and a backtick in quiz text.

## Data

All datasets are generated by seeded scripts, so they are reproducible and
nothing large is committed:

```bash
python3 scripts/make_dataset.py      # cross-sectional turbine data (Block 1-2)
python3 scripts/make_timeseries.py   # daily readings, 40 turbines (Block 2)
python3 scripts/make_corpus.py       # document corpus + gold eval set (Block 3)
```

`turbine_clean.csv` is produced by Block 1 notebook 02 and is gitignored.

## Environments

```bash
make up        # torch, keras, pgvector, mlflow
make torch     # just the torch lab + mlflow
```

Notebooks run on Python 3.12. TensorFlow has no 3.14 support, and the host runs
3.14 — this is why the containers exist. Training runs on the host with MPS;
containers are CPU-only on macOS and exist for reproducibility.

## Things that will bite you

- Rebuilding a notebook **strips its executed outputs**. Re-execute after every
  rebuild, or you commit an unrun notebook.
- `pd.Timedelta(days=n)` warns under numpy 2.5. Use `np.timedelta64(n, "D")`.
- A feature named `*_roll30` will be caught twice by a suffix filter that also
  adds it explicitly. Name derived features distinctly.
- The Things-to-Know harvester enumerates lesson directories dynamically. It used
  to use a hardcoded list, which silently excluded a whole block.
